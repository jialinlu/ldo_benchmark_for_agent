# 想请您帮忙看看这个 LDO Agent Benchmark

## 我们想做什么

我们正在尝试做一个面向 LDO 设计的 AI agent，希望它不只是会解释概念，还能看懂电路、
分析工作点和稳定性、诊断启动/瞬态/PSRR/噪声问题、提出 sizing 或架构修改，并通过仿真把
设计真正闭环。

我们的长期想法，是把强模型在 LDO 分析和设计上的能力沉淀成代码、工具和知识文档，再迁移
给能力较弱、甚至不能联网的内部 agent。但在这之前，需要先回答一个问题：**一个 AI 到底是
真的会设计 LDO，还是只是回答得很像模拟工程师？**

因此我们做了 **EvoLDO-Bench**，用来测试 LDO agent 的分析、工具使用和电路闭环能力，也用来
比较加入设计知识和仿真工具之后，agent 到底提高了多少。

当前版本是公开开发集，还不是正式的密封考试。

## Benchmark 是怎么做的

### 1. LDO 分析和推理题

目前有 **40 个题族、120 道题**，覆盖：

- 电路结构、反馈方向、body、偏置和 EN；
- 器件尺寸、偏置、补偿等变化对性能的影响；
- 不启动、输出错误、振荡、IQ 异常、PSRR 和噪声问题的诊断；
- sizing、工艺迁移、系统影响、架构选择和 design closure。

每个题族有三种版本：一道标准题、一道物理含义相同但表达不同的题，以及一道只改变一个关键
条件、从而使正确答案发生变化的反例题。这样可以减少模型靠关键词和固定模板拿分。

评分不只看最终结论，也看证据、物理机制和建议动作。反馈方向、器件类型等关键判断如果错了，
即使答案写得很长也不能得到高分。

### 2. 比较知识和仿真工具是否真的有帮助

我们会让同一个模型在相同题目、随机种子和预算下分别运行：

1. 直接回答；
2. 加入冻结版本的 LDO 设计知识；
3. 在相同知识基础上允许调用仿真。

除了分数，还记录 token、时间、成本和工具调用。希望最后能看清楚：设计知识提高了哪些能力、
仿真是否进一步有帮助、哪些仿真调用无效，以及模型是否会被错误仿真误导。

Agent 调仿真前还要说清楚想验证什么、哪些变量保持不变、改了什么和准备测什么，避免同时
改变多个变量却得出错误因果结论。

### 3. 真实晶体管级电路修改

我们还做了 **6 个基于 SKY130 和 ngspice 的 LDO 闭环任务**：

| 任务 | 预先放入的问题 |
|---|---|
| 标称工作点和 IQ | pass 管尺寸不足 |
| 冷启动 | 自偏置启动能力不足 |
| 关断和重启 | EN 相关支路错误 |
| 负载瞬态 | 补偿区间不合理 |
| 线性/负载调整率 | 低输入电压下驱动不足 |
| PVT 和器件合规 | 慢角尺寸余量不足 |

Agent 必须修改 DUT 并重新仿真，只写修改建议不能通过；修改后的电路也不能继续使用旧结果。
框架还会检查 DUT 中是否加入理想源、受控源、理想开关、`.ic` 或 `.nodeset` 等绕过真实问题
的手段。

这套 SKY130 电路大致是 1.8 V 输入、约 1.5 V 输出、0.1～1 mA 负载和 10 pF 负载电容。它只是
用来验证 agent 能否完成设计闭环，不代表先进 LDO 或产品性能。

## 当前进展

已经完成：

- 40 个原创题族和 120 道公开开发题；
- 任务、答案、评分和仿真调用格式；
- 自动运行、评分、能力分类和结果报告；
- 直接回答/增加知识/增加仿真的对照实验框架；
- 6 个 SKY130/ngspice 晶体管级闭环任务；
- candidate hash、新鲜仿真证据和基础防作弊检查；
- 自动测试和 CI；参考答案目前可以得到 100 分。

还没有完成：

- 尚未用强、中、弱多个真实模型跑完系统对照实验；
- 尚未证明这些题能够稳定区分不同能力档次的模型；
- 题目、oracle、testbench 和指标还没有经过模拟专家系统检查；
- 晶体管级任务还没有完整覆盖稳定性、PSRR、噪声、dropout、保护、Monte Carlo 和可靠性；
- 正式考试所需的隐藏题目和私有 oracle 还没有制作。

因此当前最准确的定位是：**一个已经能运行的 LDO agent 公开开发集和实验框架，但还需要
专家帮助确认它考得是否正确、是否有工程价值。**

## 想请您主要帮忙看什么

不需要填写正式表格，直接批注、聊天或列问题都可以。我们最想听到的是：

1. 当前考查的内容是否接近一个 LDO 设计 agent 真正需要的能力？
2. 哪些题只是在考术语或常识，对判断设计能力价值不大？
3. 哪些题目、oracle 或建议动作存在错误、条件不足或不能唯一作答？
4. 六个 SKY130 任务中的故障是否像真实工程问题，还是过于人为？
5. Testbench、激励、测量方法和阈值有没有明显不合理之处？
6. 当前小电流电路是否太简单，容易通过试尺寸或投机手段过关？
7. 稳定性、PSRR、噪声、dropout、保护、Monte Carlo 和可靠性中，下一步最应该补什么？
8. 哪些任务最能区分“会说术语”和“真的能推进设计”的模型？

我们不需要您为这套 Benchmark 背书，更希望您直接指出错误、过度简化和不值得继续做的部分。
没有完整解决方案也没关系，指出“这个问题不能这样考”本身就很有价值。
